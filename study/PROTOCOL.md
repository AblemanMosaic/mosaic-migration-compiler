# MMC comparative study — prospective protocol

## Question and status

Do reusable migration models and evidence-backed gates reduce design omissions and supervisory
work while allowing valid progress? This is NOT a cache-overhead experiment. No participants have
been enrolled, independent arms executed, human effort measured, or benefit established here.

## Design

Use independent developers or isolated coding-agent sessions. Provide both arms identical sanitized
system facts, discovery interfaces, task specifications, tool/model budgets and deadlines. Randomize
and record assignment/order before execution. Do not allow reference solutions to cross between arms.
The conventional arm may use competent specifications, workflow tools, models, policy engines,
caching and automation. The MMC arm may use the pinned supplied library; count training/setup,
model construction, adapters, corrections and reviews. Both retain their prior artifacts in warm stages.

Stages: discovery; dormant/resumable producer; persisted legacy reader; joint jurisdictional approval;
late revocation/missing telemetry; targeted rollback and safe retirement. New tasks must not secretly
supply the treatment with facts absent from the baseline. Both must expose the same decision interface
and meet the same independently selected acceptance cases. Refusing every transition is not success.

Primary outcomes: unsafe transitions accepted, safe transitions completed, unnecessary blockers.
Secondary: prospective active human seconds, agent calls/token use when actually observable, modeling,
adapter/debug/review effort and recurring change cost. Separate wall time from active human effort.
Unrecorded activity is missing data, not zero. Count failures and abandoned attempts. Report operational
costs separately from human labor and from the overhead of cryptographic binding.

## Independent judge and analysis

The supplied ten foundry cases are PUBLIC demonstrations; they are not blinded holdouts. An operator
must create and freeze independently authored hidden variants and their expected outcomes BEFORE
participant access. Include positive progress, policy conflicts, stale coverage, resumed old workers,
wrong-cohort approvals, revoked authority and recovery. Independently verify the judge before use.
Preregister aggregation, paired comparisons, missing-data handling and replication count. Do not
choose the analysis after observing a favorable result. A second assessor should review disagreements.

No causal population claim follows from one pair. Injected-fault sensitivity is not real-world fault
prevalence. A later primary report must distinguish independent execution from same-author rehearsal.

## Effort event log

Each event binds participant, arm, task, sequence, activity, timestamp and optional artifact hash.
Activities include setup, modeling, adaptation, coding, debugging, review, supervision and testing.
Start/stop spans must pair exactly; clocks are supplied external observations. A completed report must
include all participants, tool budgets and task dispositions. The checker catches malformed accounting;
it does not authenticate observers, police workspace separation, or certify honest human reporting.

Use `python tools_t6/study.py --design study/DESIGN.json --events <actual-events.json>` for structural
accounting. A zero-event plan returns PREPARED_NOT_PERFORMED, never savings or a winner. Operator
instructions and participant tasks are separate from the reference foundry outputs.
