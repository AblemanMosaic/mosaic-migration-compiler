# Model, realization and evidence are separate

constitution/FREEZE.json binds the full W00-W13 program and its exact requirements/cases/gates.
model/foundation/CONTRACT.json binds the selected program, wire schema, metamodel and normative
protocol; COMMITMENT.json records its separate profile root. The installed _pins.py selects these
candidate roots explicitly. It is an author-selected pin, not independent ratification.

REALIZATION-BINDING.json connects current foundation requirements to exact implementation symbols,
source files and named tests. check_model.py verifies those hashes/references and optionally the
current source-bound test results. This is traceability, NOT a proof of semantic equivalence.

A replacement in Python, Rust or another toolchain must preserve canonical bytes, reference/scope
checks, declared set normalization, dependency order, exact typed results, limits, guard meaning and
the no-effect boundary. It renews implementation/build/test evidence. A compatible implementation
may retain the profile root; incompatible semantics need an explicit versioned successor contract.

Known-answer vectors cover selected encoding, hash and model cases. Their model roots are reference-
assisted; the authored acceptance tests supply separate assertions about order, guards and refusals.
Finite passing vectors do not prove correctness or independent security qualification. No automatic
code generator, theorem prover or full alternative-language realization is included in Capability Layer T1.
