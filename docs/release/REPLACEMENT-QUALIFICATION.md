# Replacing a realization

Pin the original program and all selected T1–T5 semantic contracts independently. A replacement may
change language or internals, but must preserve canonical byte rules, profile selection, exact
result/refusal types, resource bounds, scope and temporal semantics, dependencies, authority ceilings,
and effect/recovery meaning. Model identity is not the same as source/binary identity.

Use frozen corpora and independent positive/negative cases. Exact canonical result equality matters:
booleans are not integers; missing is not null; current eligibility is not historical validity.
Execution evidence must bind the new evaluator identity and toolchain. Do not regenerate expected
answers to make a port pass. These corpora are same-author reference-assisted fixtures, not a proof
of whole-program equivalence or independent cryptographic certification.

Storage substitution needs its own atomicity/isolation/idempotency/restart evidence. Matching a
hash does not qualify a new database or external adapter. Target-platform tests must run on the
claimed environment; unavailable legs remain blocked. Observer coverage and real authority require
separate deployment acceptance even when every deterministic fixture agrees.

The five existing model checkers establish reference/symbol/test traceability. The T6 checker maps
six additional delivery requirements with explicit dispositions; it cannot turn a prepared study
into a performed study or a native-admission work order into actual host mediation.
