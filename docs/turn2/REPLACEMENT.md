# T2 contract and replacement realization

Keep T1's exact program root, foundation contract and expected corpus. T2-D1 has a separate
CONTRACT.json/COMMITMENT.json and REALIZATION-BINDING.json under model/domain-t2/. The sixteen
W03-W05 requirements bind to concrete symbols, test identities and the current source files.
The model checker never regenerates a contract or corpus to make the implementation pass.

A replacement must preserve exact input admission, scopes, half-open intervals, typed outcomes,
unknown handling, condition semantics, state constraints, search-budget uncertainty and no-effect
boundaries. Plan tie order is part of reproducibility, not a claim of operational optimality.
The 38 new full-record vectors are reference-assisted, with independently authored status oracles;
passing them is not proof of equivalence. Add independent cases and platform-specific checks.

T2 lives outside mosaic_mmc, so the T1 compiler realization digest and its known-answer results
remain exact. Distribution metadata and the foundation realization binding are renewed where
packaging metadata changed; the underlying frozen semantic files are not rewritten.

No SDK or user-supplied plugin loader is shipped in this turn. New qualified profiles can be added
as explicitly installed extension code/data without changing the twelve T1 primitives. Runtime
handler qualification and portable SDK discovery are later T4 obligations.
