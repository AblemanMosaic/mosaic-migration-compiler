# Freeze and amendment policy
This is a construction freeze, not public ratification. PROGRAM, REQUIREMENTS, ACCEPTANCE, GATES,
CLAIMS, DECISIONS, RISKS, DEPENDENCIES and FOUNDATION-CONTRACT are frozen before runtime implementation.
The freeze is a closed file inventory with a domain-separated root. A verifier requires an accepted
expected root; a downloaded file that repeats its own hash is not authentication.
Do not overwrite frozen files to pass tests. Preserve the prior set and add an explicit amendment
record with affected requirements, reason, predecessor/successor roots, scope and approval status.
A runtime bug fix preserving the contract changes the realization, not necessarily this contract.
Unknown external gates remain open. Capability Layer T1 success never completes Capability Layers T2–T6 or proves productivity.
