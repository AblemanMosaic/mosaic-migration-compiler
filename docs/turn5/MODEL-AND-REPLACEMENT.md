# T5 contract, realization and repeatability

The full program root and T1–T4 meanings retain their exact bytes. T5-Q1 commits ten finite
qualification scenarios and eight W12 obligations. Its source implementation and evidence
are bound separately. Verification never rewrites the accepted contract or expected corpus.

A replacement foundry must preserve admitted inputs, actual evaluator/controller use, exact
scope and status meaning, all refusal/repair pairs, and the distinction between recorded-
journal inspection and fresh simulation replay. Reusing the same test labels is insufficient.
A model check verifies referenced bytes, symbols and recorded test identities—not correctness
of all possible executions, observation truth, or native program admission.

Rebuild determinism means serializing the SAME frozen tree. Rerunning timestamped test logs,
changing installed dependency versions or changing an implementation can change evidence.
The scenario trace itself excludes paths/PIDs/durations and is replayable under the same
qualified realization and fixture schedule. The externally supplied expected root remains
necessary for recognition; self-hashing a report is not publisher authentication.

Current runtime profiles and native adapter dependencies are not force-upgraded by installing
this qualification distribution. The a4 workbench label remains a historical implementation
identifier; importlib.metadata.version('mosaic-migration-compiler') reports a5. The selected
Python and OS, optional crypto, real custody, clock/floor protection and production adapters
remain independent qualification assumptions.
