# Realization replacement and version sovereignty

Pin the original program and T1/T2/T3 models plus the T4 interface contract. A new realization must
preserve exact typed wire results, signed native semantics, current-view/reader separation, unknown
and negative evidence, one-claim scope, replay behavior, and effect boundaries. The compiler kernel is
not silently rewritten to support extensions. Source realization hashes must change when its code
changes; contract hashes change only through an explicit semantic amendment.

T4 known-answer vectors compare exact full canonical results or exact refusal codes. Their expected
results are reference-assisted, not an independent mathematical oracle. Passing them is necessary
local evidence, not proof of all program behavior. Host collectors and exports require additional
platform/mechanism tests; a cryptographic corpus cannot qualify actual filesystem or network custody.

The model checker binds fifteen requirement rows to references, symbols and executed named tests.
It preserves W11-R04 native-host limitations and does not infer independent approval. A replacement
must renew its own realization/evidence map; a shared semantic contract transfers neither operating
permission nor a customer's version choice.
