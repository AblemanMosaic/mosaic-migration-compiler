# Capability Layer T4 decisions (pre-implementation)

T4-I1 is additive. T3 runtime bytes and its evidence rules stay pinned.
The GUI is a client of the same bounded data ABI, not a second court. Read/import does not
adopt context or touch a controller. Agent submissions require exact work and snapshot pins.
A host-only admission method appends evidence under the original journal CAS; target effects
remain T3 explicit Python calls. The GUI does not approve/sign/commit production changes.

SDK handlers are supplied by trusted host code, never model strings. A fixture qualification
is same-author evidence for specific cases, not a safety sandbox. Filesystem/SQLite/HTTP collectors
are explicitly selected by the host. Pure release/deployment/job parsers inspect supplied snapshots.
No live Kubernetes, corporate API, or external P/PPI credentials/endpoints are introduced.

Use known a4 CMBA and DKN rc5 wheels only for optional bounded read adapters after byte checks;
do not import the unqualified integrated successor. Missing integrations remain visible.
Native P/PPI admission cannot be closed in this environment from the supplied handoffs.

Dark-mode native Tk workbench, optional system Tk, no GUI dependency in the headless core.
Local export is create-only and confirmed by the host; no overwrite or remote publication.
