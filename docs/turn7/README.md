# Release Convergence r013 — current product and integrations

MMC public v0.1 / Python distribution 0.1.0a9 Release Convergence r013 makes Capability Layer the
canonical name for T1–T6 while preserving their stable compatibility identifiers. It includes the
r008-r011 dependency-security and publication repairs and the source-only Apache-2.0 Git projection.
It repairs the successor realization regressions and replaces
projection-only integration evidence with executed paths. The current workbench demo and all
33 T4 interface vectors are rebound to the portable realization identity. Qualification binds
the source before and after every suite and integration, records exact test identities/logs,
executes a CMBA binding, produces a five-event UCM CampaignJournal, and performs one real
disposable SQLite migration with a resumed legacy worker through the native T3 controller.
The run includes lost-ack reconciliation after controller restart, compensating recovery,
re-cutover, and retirement. The original 84 requirements,
100 acceptance cases, and T1–T6 capability-layer interfaces remain available. Release Convergence
is not a seventh capability layer. Historical exact-byte assertions
superseded by the successor are reported separately, never counted as current behavioral passes.

Use `mmc-product capabilities` for the complete product inventory and `mmc-product integrations`
for exact dependency status. The historical `mmc`, `mmc-t2`, `mmc-t3`, `mmc-agent`, and
`mmc-foundry` entry points remain versioned compatibility surfaces.

The disposable run compares source and destination inventories and resumes the same child process
that waited before migration. Its SQL changes are performed by a non-production SQLite adapter
admitted by the native controller. Retirement coverage and approval are signed public test fixtures,
not external authorization. Stage-I1 compares structural contracts against the immutable T6 baseline and records
native reconciliation separately from UCM's effect declaration. It does not prove complete current
runtime equivalence. Read [agent surface](AGENT-SURFACE.md); `mmc-product protocol` exposes 47
uniformly framed operations and the explicit host adapter boundary.

`mmc.adapter-transport.v1`, using fresh private-pipe credentials, authenticated challenges,
implementation/target pins, deadlines and cancellation. Unknown outcomes reconcile from the
target's durable ledger. `mmc-product verify-target-migration` exercises that path in a disposable
database. Release qualification and installation use the exact offline wheel closure in
`baseline/offline` or an explicitly admitted native full qualification bundle; no system-site
packages are borrowed. Revision r007 checks dependency files before site startup, accounts for
SQLite conflict deletion at source fences, and provides an exact cross-host qualification handoff.
Native full profiles add Pillow for the GUI screenshot oracle. A prepared handoff is not an
executed platform qualification or independent external approval.
